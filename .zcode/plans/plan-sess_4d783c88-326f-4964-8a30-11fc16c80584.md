## P2: 入库前校验渠道可用性

### 设计思路

采集源拉到模型列表 → 入库前查一下 `price_snapshots` 表，看当前配置的渠道中是否有任何渠道为该 model_id 配过价格。如果没有可用渠道，仍写 log（因为模型确实存在于上游），但在 log 的 `provider` 字段标记来源渠道，并在前端加"⚠️ 无可用渠道"提示。**不阻断入库**——因为用户可能之后会配置对应渠道，但要让用户明确知道"这个模型目前你的渠道打不通"。

### 改动文件

**1. `db/crud.py` — 新增 `has_available_channel` 查询函数**
```python
async def has_available_channel(session: AsyncSession, model_id: str) -> bool:
    """检查当前是否有 active channel 为该 model_id 配过价格 (price_snapshots).
    
    用于 model_sync 入库前判断 "这个模型是否有渠道能真正路由".
    """
    from db.models import PriceSnapshot, Channel
    stmt = (
        select(PriceSnapshot.id)
        .join(Channel, PriceSnapshot.channel_id == Channel.id)
        .where(PriceSnapshot.model == model_id)
        .where(Channel.status == "active")
        .limit(1)
    )
    result = await session.execute(stmt)
    return result.scalar_one_or_none() is not None
```

**2. `intelligence/model_sync.py` — `process_model_item` 入库时标记渠道可用性**
- 在写 create log 前调用 `has_available_channel`
- 如果无可用渠道，在 `new_value` JSON 中加 `"channel_available": false` 标记
- 这样前端展示时能看到这个标记

**3. `dashboard/static/app.js` — `renderPendingReview` 展示渠道可用性**
- 解析 new_value JSON 时，如果 `channel_available === false`，在卡片上加红色"⚠️ 无可用渠道"标签

## P3: 消除 pending log 重复堆积

### 设计思路

参考 `CrossSourceDiscrepancy` 表的 `uq_cross_source_key (model_id, field_changed, status)` 唯一约束 + upsert 模式。对 `model_capabilities_log` 做：

1. 加唯一约束 `(model_id, field_changed, approved)` — 当 `approved=0` 时，同 model+field 只保留一条 pending 行
2. `log_capability_change` 改为 upsert：如果同 `(model_id, field_changed, approved=0)` 的行已存在，更新该行的 `new_value`/`confidence`/`created_at`，而非 INSERT 新行

### 改动文件

**1. `db/models.py` — `ModelCapabilitiesLog` 加唯一约束**

SQLite 不支持在已有表上加带 WHERE 的 partial unique index（通过 `CREATE UNIQUE INDEX ... WHERE`），但可以用普通唯一索引。考虑到 resolved（approved=1）的行也需要保留历史，用 partial unique index：

```python
# V4.8.6: pending 去重 — 同 (model_id, field_changed) 在 approved=0 时只保留 1 条.
# 用 partial unique index (SQLite/PostgreSQL 均支持), approved=1 的审计行不受约束.
__table_args__ = (
    Index(
        "uq_mcl_pending", "model_id", "field_changed",
        unique=True,
        sqlite_where=text("approved = 0"),
        postgresql_where=text("approved = 0"),
    ),
)
```

**2. `db/init_db.py` — 迁移：清理历史重复 pending 行 + 建索引**

```python
# V4.8.6: model_capabilities_log pending 去重
# 1) 清理历史重复 approved=0 行 (同 model_id+field_changed 只保留最新一条)
dup_check = await conn.execute(text(
    "SELECT COUNT(*) FROM ("
    "  SELECT model_id, field_changed FROM model_capabilities_log"
    "  WHERE approved = 0"
    "  GROUP BY model_id, field_changed HAVING COUNT(*) > 1"
    ")"
))
dup_count = dup_check.scalar()
if dup_count and dup_count > 0:
    logger.warning("迁移: model_capabilities_log 发现 %d 组重复 pending 行, 清理保留最新", dup_count)
    await conn.execute(text(
        "DELETE FROM model_capabilities_log WHERE id NOT IN ("
        "  SELECT MAX(id) FROM model_capabilities_log"
        "  WHERE approved = 0"
        "  GROUP BY model_id, field_changed"
        ") AND approved = 0"
    ))
# 2) 建 partial unique index
result = await conn.execute(text(
    "SELECT name FROM sqlite_master WHERE type='index' AND name='uq_mcl_pending'"
))
if not result.fetchone():
    await conn.execute(text(
        "CREATE UNIQUE INDEX uq_mcl_pending ON model_capabilities_log(model_id, field_changed) WHERE approved = 0"
    ))
    logger.info("迁移: model_capabilities_log 添加 pending 去重索引 (V4.8.6)")
```

**3. `db/crud.py` — `log_capability_change` 改为 upsert 逻辑**

```python
async def log_capability_change(
    session, model_id, field_changed, old_value, new_value,
    source="ai_infer", confidence=None, approved=0, provider=None,
) -> None:
    from db.models import ModelCapabilitiesLog
    from sqlalchemy import select

    # V4.8.6: pending 行 (approved=0) 做 upsert — 同 model+field 已有 pending 行则更新, 不新增
    if approved == 0:
        stmt = select(ModelCapabilitiesLog).where(
            ModelCapabilitiesLog.model_id == model_id,
            ModelCapabilitiesLog.field_changed == field_changed,
            ModelCapabilitiesLog.approved == 0,
        ).limit(1)
        existing = (await session.execute(stmt)).scalar_one_or_none()
        if existing:
            existing.old_value = old_value
            existing.new_value = new_value
            existing.confidence = confidence
            existing.provider = provider or existing.provider
            # 更新时间戳 (让用户看到最新扫描结果)
            existing.created_at = datetime.now()
            await session.flush()
            return

    row = ModelCapabilitiesLog(
        model_id=model_id, field_changed=field_changed,
        old_value=old_value, new_value=new_value,
        source=source, confidence=confidence,
        approved=approved, provider=provider,
    )
    session.add(row)
    await session.flush()
```

## P4: DeepSeek 模型列表采集修复

### 问题分析

DeepSeek 官方文档（https://api-docs.deepseek.com/zh-cn/）：
- base URL：`https://api.deepseek.com`
- 获取模型列表路径：`/models`（文档明确写的是 `GET /models`，没有 `/v1` 前缀）
- 文档首页列出三个可用模型：`deepseek-v4-flash`、`deepseek-v4-pro`、`deepseek-v4-flash-vision-exp`

当前代码配置：
- `DeepSeekModelListSource`（deepseek.py:58）：`api_endpoint="https://api.deepseek.com/v1"`
- `fetch_models_via_api`（api_models.py:106）：`url = f"{base_url}/models"` → 实际请求 `https://api.deepseek.com/v1/models`

DeepSeek 的 base URL 是 `https://api.deepseek.com`（不带 `/v1`），但 OpenAI SDK 默认会加 `/v1` 前缀。DeepSeek 为了兼容 OpenAI SDK，`/v1/models` 和 `/models` 都应该可用。但文档明确写的是 `/models`，且当前配置 `https://api.deepseek.com/v1` + `/models` = `https://api.deepseek.com/v1/models`。

**需要验证**：当前 `/v1/models` 是否能返回 `deepseek-v4-flash-vision-exp`。如果 DeepSeek 的 `/v1/models` 和 `/models` 返回内容一致，则模型未入库的原因是采集源 api_key 未配置或失效（scheduler.py:415-420 的静默跳过分支）。如果返回不一致，需要改 endpoint。

### 改动文件
