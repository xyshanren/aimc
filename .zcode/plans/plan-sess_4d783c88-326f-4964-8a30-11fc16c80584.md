## Batch 1 (P5): drop_params 自动检测

### 问题
`drop_params` 需手动配置。用户不知道这个参数存在，上游返回 400 "unsupported parameter" 后请求直接失败，没有任何自动学习机制。

### 设计思路
在 `_forward_normal` 中捕获上游 400 响应体，解析错误信息中提到的参数名（OpenAI 风格 `"param"` 字段 / 消息文本中提取），如果该参数不在 `ALWAYS_KEEP_PARAMS` 且不在当前 channel 的 drop_params 中，则自动追加。流式路径同样在 `_forward_stream` 的 status_code 判断处补一个 400 检测分支。

**参数名提取规则**（覆盖主流上游错误格式）:
1. OpenAI 风格: `{"error": {"param": "reasoning_effort", ...}}`
2. 消息文本提取: `"unsupported parameter: 'reasoning_effort'"` / `"unknown parameter reasoning_effort"` / `"unrecognized request argument supplied: 'reasoning_effort'"`
3. 只提取 body 顶层已存在的 key（避免误杀），只提取已知 OpenAI 参数白名单中的名字（`reasoning_effort`, `max_tokens`, `temperature`, `top_p`, `frequency_penalty`, `presence_penalty`, `logprobs`, `top_logprobs`, `n`, `stop`, `seed`, `response_format`, `tools`, `tool_choice`, `user`, `metadata`, `stream_options`, `service_tier`, `prompt_cache_key`, `store`, `logit_bias`）

**安全守卫**:
- 只在 channel 配了 `auto_drop_params=1`（新字段，默认 1）时自动写入
- 自动写入用 fire-and-forget 异步 DB 更新，不阻塞响应
- 同一参数不重复追加（先 parse 现有 drop_params，去重）
- 写入后触发 `route_engine.invalidate_channel(channel_id)` 刷新缓存
- `ALWAYS_KEEP_PARAMS` 永远不会被自动加入

**3. `gateway/proxy.py` — 新增 `_extract_unsupported_params` + `_auto_learn_drop_params`**
```python
# V4.8.7: 已知 OpenAI 请求参数白名单 (只对这些参数做自动 drop 学习)
_KNOWN_REQUEST_PARAMS = frozenset({
    "reasoning_effort", "max_tokens", "temperature", "top_p",
    "frequency_penalty", "presence_penalty", "logprobs", "top_logprobs",
    "n", "stop", "seed", "response_format", "tools", "tool_choice",
    "user", "metadata", "stream_options", "service_tier",
    "prompt_cache_key", "store", "logit_bias",
})

def _extract_unsupported_params(response: httpx.Response, body: bytes) -> list[str]:
    """从上游 400 响应中提取被拒绝的参数名"""
    try:
        data = response.json()
    except Exception:
        return []
    err = data.get("error", data) if isinstance(data, dict) else {}
    if not isinstance(err, dict):
        return []
    candidates = []
    # 1. OpenAI 风格 error.param
    param = err.get("param")
    if isinstance(param, str) and param:
        candidates.append(param)
    # 2. 从 message 文本提取
    msg = err.get("message", "")
    if isinstance(msg, str):
        import re
        # 匹配引号包裹的参数名 或 "parameter: xxx" 格式
        for m in re.finditer(r"['\"]([a-z_][a-z0-9_]*)['\"]", msg):
            candidates.append(m.group(1))
        # "unrecognized ... argument ... 'xxx'" / "unknown parameter 'xxx'"
    # 过滤: 只保留白名单 + 在 body 顶层存在的 + 不在 ALWAYS_KEEP_PARAMS
    try:
        body_dict = json.loads(body)
    except Exception:
        body_dict = {}
    result = []
    seen = set()
    for p in candidates:
        p = p.strip().lower()
        if p in seen:
            continue
        if p in ALWAYS_KEEP_PARAMS:
            continue
        if p not in _KNOWN_REQUEST_PARAMS:
            continue
        if p not in body_dict:
            continue
        seen.add(p)
        result.append(p)
    return result


async def _auto_learn_drop_params(channel: dict, params: list[str]):
    """异步写入: 把新参数追加到 channel.drop_params, 刷新缓存"""
    try:
        from db.engine import async_session_factory
        from db.models import Channel
        from sqlalchemy import select
        from gateway.router import route_engine

        async with async_session_factory() as session:
            ch = (await session.execute(
                select(Channel).where(Channel.id == channel["id"])
            )).scalars().first()
            if not ch:
                return
            existing = _parse_drop_params(ch.drop_params)
            new_params = [p for p in params if p not in existing]
            if not new_params:
                return
            merged = existing + new_params
            ch.drop_params = json.dumps(merged, ensure_ascii=False)
            await session.commit()
            logger.warning(
                f"V4.8.7 auto-drop: channel={channel['name']} "
                f"learned {new_params} (drop_params={merged})"
            )
        try:
            await route_engine.invalidate_channel(channel["id"])
        except Exception:
            pass
    except Exception as e:
        logger.debug(f"V4.8.7 auto-learn failed (non-fatal): {e}")
```

## Batch 2 (P6): 分时段定价 (工作日/周末)

### 问题
DeepSeek 官方峰谷计费: 工作日 9:00-12:00 和 14:00-18:00 为高峰, 其余时段(含周末全天)为低谷. 当前 `_match_time_range` 只比较小时, 无工作日/周末概念. 种子数据 `"00:00-08:00"` 是错的.

### 设计思路
扩展现有 `time_range` 字符串语法（不加新列，不加迁移）:
- `"工作日09:00-12:00"` → 工作日 9-12 点匹配
- `"工作日14:00-18:00"` → 工作日 14-18 点匹配
- `"周末全天"` → 周末全天匹配
- `"非高峰全天"` → 非高峰时段全天匹配 (用于 offpeak 行兜底)
- 保持向后兼容: `"全天"` / `"HH:MM-HH:MM"` 语义不变

`_match_time_range` 签名改为接收 `now: datetime` 而非 `current_hour: int`，内部判断 weekday + hour。所有调用点（4 处 router.py + 1 处 proxy.py）改传 `datetime.now()`。

DeepSeek 种子数据改为:
- `("deepseek-v4-pro", "peak", "工作日09:00-12:00", 8.0, 24.0)` — 高峰原价
- `("deepseek-v4-pro", "peak", "工作日14:00-18:00", 8.0, 24.0)`
- `("deepseek-v4-pro", "offpeak", "非高峰全天", 4.0, 16.0)` — 低谷半价 (原 normal 价)
- `("deepseek-v4-flash", "peak", "工作日09:00-12:00", 2.0, 4.0)`
- `("deepseek-v4-flash", "peak", "工作日14:00-18:00", 2.0, 4.0)`
- `("deepseek-v4-flash", "offpeak", "非高峰全天", 1.0, 2.0)` — 低谷半价

注意: 原来的 `"normal"` 行用 `"全天"` 改为 `"offpeak"` + `"非高峰全天"`，这样高峰时段 offpeak 行不匹配，peak 行匹配；非高峰时段 peak 行不匹配，offpeak 行匹配。

### 改动文件

**1. `gateway/router.py` — `_match_time_range` 重写**
```python
def _match_time_range(self, time_range: str, now: datetime) -> bool:
    """判断当前时间是否在时段范围内 (V4.8.7: 支持工作日/周末)

    支持格式:
    - "全天" / "" → 始终匹配
    - "00:00-08:00" → 每天 0-8 点 (向后兼容)
    - "工作日09:00-12:00" → 工作日 9-12 点
    - "工作日14:00-18:00" → 工作日 14-18 点
    - "周末全天" / "周末00:00-24:00" → 周末
    - "非高峰全天" → 非高峰时段 (工作日非9-12/14-18 + 周末全天)
    """
    if not time_range or time_range == "全天":
        return True

    is_weekend = now.weekday() >= 5  # 周六=5, 周日=6
    current_hour = now.hour

    # "非高峰全天": 工作日非高峰时段 + 周末全天
    if time_range == "非高峰全天":
        if is_weekend:
            return True
        # 工作日: 不在 9-12 和 14-18
        in_peak = (9 <= current_hour < 12) or (14 <= current_hour < 18)
        return not in_peak

    # "周末全天" / "周末..." → 只在周末匹配
    if time_range.startswith("周末"):
        if not is_weekend:
            return False
        rest = time_range[2:]  # 去掉 "周末"
        if not rest or rest == "全天":
            return True
        return self._match_hour_range(rest, current_hour)

    # "工作日..." → 只在工作日匹配
    if time_range.startswith("工作日"):
        if is_weekend:
            return False
        rest = time_range[3:]  # 去掉 "工作日"
        if not rest or rest == "全天":
            return True
        return self._match_hour_range(rest, current_hour)

    # 向后兼容: 纯 "HH:MM-HH:MM" → 每天该时段
    return self._match_hour_range(time_range, current_hour)


def _match_hour_range(self, time_range: str, current_hour: int) -> bool:
    """解析 "HH:MM-HH:MM" 并判断 current_hour 是否在 [start, end) 内"""
    try:
        parts = time_range.split("-")
        if len(parts) != 2:
            return True
        start_hour = int(parts[0].split(":")[0])
        end_hour = int(parts[1].split(":")[0])
        return start_hour <= current_hour < end_hour
    except (ValueError, IndexError):
        return True
```

## Batch 3 (P7): 429 渠道定位

### 问题
组路由 `tier:strong` / `tier:code` 报 429 时用户看不到是哪个渠道余额不足。重试循环里每个失败的 channel 只写 server log，最终返回的 503 `"All upstream channels failed"` 无渠道信息。`CooldownManager.snapshot()` 存在但无 API 暴露。

### 设计思路
两管齐下:
1. **响应头注入失败渠道链**: 在 routes.py 重试循环中收集每个失败渠道的 `(channel_name, account_name, status_code)`，最终返回时通过 `X-AIMC-Failed-Channels` 响应头传递（JSON 格式），让 hermes-agent-cn 能在 UI 展示
2. **响应体增强**: 503 兜底响应的 error.message 里列出失败渠道
3. **cooldown snapshot API**: 新增 `GET /api/cooldown` 端点暴露 `cooldown_manager.snapshot()`，同时在 snapshot 里补充 channel_name / account_name（通过 router cache 反查）
4. **stream 429 补齐**: `_forward_stream` 也加 429 cooldown marking（当前只有 `_forward_normal` 有）

### 改动文件

**1. `gateway/routes.py` — 重试循环收集失败渠道**
在 retry loop 之前加 `failed_channels = []`，在 failover continue 前追加:

**2. `gateway/cooldown.py` — `snapshot()` 增强（返回 reason + remaining）**
```python
def snapshot(self) -> dict[int, dict]:
    """调试用: 当前所有冷却状态快照 (V4.8.7: 加 reason + remaining)"""
    now = time.time()
    result = {}
    for aid, s in self._state.items():
        remaining = 0.0
        if s.get("cooldown_until") and s["cooldown_until"] > now:
            remaining = s["cooldown_until"] - now
        result[aid] = {
            "count": s.get("count", 0),
            "cooldown_until": s.get("cooldown_until"),
            "remaining_seconds": round(remaining, 1),
            "in_cooldown": remaining > 0,
        }
    return result
```
