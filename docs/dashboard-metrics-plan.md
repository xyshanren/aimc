# 看板指标体系统一规划 (V6.2 提案, 待评审)

> 2026-09-05 · 源起: 看板审查第 3 项 — 指标不统一/有歧义 (如左上角 glm 渠道金额与命中率)。
> 本文档只做规划, 未实施。批准后按分期落地。

## 1. 问题盘点 (现状审计)

### 1.1 同名不同义 (最易误导)

| 显示名 | 出现位置 | 实际口径 | 冲突对象 |
|---|---|---|---|
| 节省 | 顶部 KPI 卡「节省金额」、状态栏「saved」 | **Cache 节省** = 缓存折扣省下的钱 (saved_cost_cny) | 成本审计「节省」= **标价−实付** (list_cost−cost) |
| 命中率 | 状态栏「93.5% hit」、KPI 卡「Cache 命中率」、Cache 明细列 | **Cache 命中率** = cached_tokens/input_tokens | 组路由卡「组路由命中率」= **路由成功率** (路由到非首选渠道的比例口径) |
| 节省 | Cache 明细每行「节省」 | Cache 节省 (按渠道/模型) | 同名但与成本审计「节省」语义不同, 同屏出现 |

### 1.2 格式不统一

- 金额: 状态栏/KPI 曾用 `¥195.1193` (4 位小数), Cache 明细 `¥100.5518` (4 位), 成本审计 `¥188.56` (2 位)。P1-2 fmtCNY 落地后仍有遗漏入口 (状态栏 status-route 文案拼接)。
- 比率: `93.5%` / `95.8%` / `0.0%` 基本统一, 但无「未定义」态 (无数据时显 0.0% 有歧义)。
- Token: `toLocaleString()` 全千分位, 大数可读性差 (148,686,498), 无 K/M 缩写选项。
- 延迟: 平均延迟直接 `16026 ms`, 未做 ms→s 自适应。

### 1.3 窗口/口径不统一

- 全局时间范围 (24h/7d/30d) 已覆盖: usage/cache/cost/per-user API。
- **例外**: 组路由命中率卡 htmx 直连 `/api/stats/group_routing`, 未传 `days`, 固定后端默认 7 天 → 全局切 24h/30d 时该卡不动, 与副标题「近 7 天」可能撒谎。
- 状态栏 cache 行 vs KPI 卡: 同一数据双入口展示, 数值恒等但口径标注缺失。

### 1.4 信息架构问题

- 状态栏 (页头) 承担了本应属于 KPI 层的业务指标 (cache 渠道/节省/命中率), 页头应只放系统健康摘要。
- 指标口径无任何 UI 内解释, 新用户无法区分两个「节省」。

## 2. 统一指标体系设计

### 2.1 指标命名规范 (显示层)

| 域 | 统一显示名 | 口径 | 备注 |
|---|---|---|---|
| Cache | **Cache 节省** | saved_cost_cny (缓存折扣) | 原「节省金额」「saved」全部收敛到这个名字 |
| Cache | **Cache 命中率** | cached/input | 原「hit」「命中率」(cache 语境) |
| 成本 | **实付成本** | cost | 原「实付」 |
| 成本 | **官方标价** | list_cost_estimate | 保持 |
| 成本 | **标价节省** | list−paid | 原「节省」改名, 与 Cache 节省彻底区分 |
| 成本 | **标价覆盖率** | 有标价行占比 | 保持 |
| 路由 | **路由成功率** | group_routing 命中口径 | 卡片与表头改名, 不再叫「命中率」 |
| 用量 | 请求 / Token / 平均延迟 | 现状 | Token 增加 K/M 缩写 |

### 2.2 格式规范 (前端 fmt 模块集中)

- `fmtCNY(n)` — 2 位小数, <0.01 显 `<¥0.01` (已有, 补齐遗漏调用点)。
- `fmtPct(x)` — 1 位小数; 分母为 0 时显 `—` 而非 `0.0%`。
- `fmtTokens(n)` — ≥1e6 显 `x.xM`, ≥1e3 显 `x.xK`, 否则原值; 表格保留千分位开关。
- `fmtLatency(ms)` — <1000 显 `xxx ms`, ≥1000 显 `x.x s`。
- 所有 fmt 函数集中到 app.js 顶部 fmt 区, 禁止在渲染代码里手拼 `¥` + toFixed。

### 2.3 窗口规范

- 任何时序指标卡副标题必须展示当前窗口, 且随全局 range 联动。
- group_routing htmx 调用补 `days` 参数 (后端 `days: int = 7` 已支持, 纯前端改动 + 触发方式从纯 htmx 改为 JS 带参或 htmx `hx-vals`)。
- 范围切换 (`applyTimeRange`) 的重拉清单里加入 group routing 刷新。

### 2.4 信息架构 (轻改, 不动三列布局)

- 状态栏 cache 行改为系统摘要: `运行中 · 近1h 请求 N · 活跃告警 M` (或直接删除业务数字, 只留服务状态); Cache 三指标只在 KPI 卡出现一次。
- 卡片表头支持 `title` tooltip: 悬停显示口径一句话 (如「标价节省 = 官方标价 − 实付, 只统计标价已知行」)。
- 指标字典: app.js 顶部维护 `METRIC_DEFS` 常量 (显示名/口径/格式函数), 渲染处只引用字典, 后续新指标先入字典。

## 3. 分期落地

| 期 | 内容 | 改动面 | 风险 |
|---|---|---|---|
| **Phase 1** | 命名统一 (标价节省/路由成功率/Cache 节省) + fmt 模块补齐 (fmtPct/fmtTokens/fmtLatency) + 状态栏去重 | 纯前端 app.js/index.html | 低 |
| **Phase 2** | group_routing days 参数 + 范围联动刷新 + 表头 tooltip (指标字典) | 前端 + routes.py 一处参数 (已支持 days, 无 schema 变更) | 低 |
| **Phase 3** (可选) | 更大信息架构重排 (卡片合并/新增对比视图) | 待 Phase 1/2 上线后按观感决定 | 中 |
